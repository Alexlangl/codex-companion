# 会话修复备份

启动时的 provider namespace 迁移只修改会话的 `session_meta`。新备份在
`backups/codex-companion/repair/<时间戳>/history-patches-v1/` 中保存对应会话路径、
行号、修改前和修改后的原始元数据行，不再复制对话和工具输出。
迁移时通过 `companion_usage_provider` 保留来源，统计优先读取该标记，避免切换
账号后把历史用量改归当前账号。旧中转记录没有上游身份时不推断具体账号。同一目标的重复修复
没有修改时不会创建快照，也不会替换原文件。

会话逐行处理，只在发现修改时创建同目录临时文件。恢复日志持久化后才原子替换会话；
保留权限、原始换行和未修改的字节。提交前检查文件大小和修改时间，发现外部修改就
放弃覆盖。这不是跨进程文件锁：调用者仍应在修复前停止写入会话的 Codex 客户端。

后续修复步骤失败时，恢复日志只还原对应的元数据行，保留追加的事件。元数据不匹配
或文件被截断时拒绝覆盖，并保留备份供排查。数据库和插件仍保存完整文件，旧版完整
会话备份也能通过原来的回滚逻辑恢复。恢复日志用于撤销迁移，不是脱离原会话文件的
独立历史归档；跨多次迁移恢复应从最新快照逐次向前撤销。

每次成功产生修复快照后，按时间淘汰旧快照，最多保留 2 份，总大小目标为 256 MiB。
最新恢复点始终保留，即使单份超过容量目标。早期位于 `backups/codex-companion/`
下的时间戳目录，只有符合已知历史备份结构时才纳入清理；包含配置、身份文件或未知
条目的目录不参与清理。当前安装引用的备份、标记为 `rollback-failed.txt` 的恢复失败
快照受到保护，不计入自动淘汰范围。清理出错会记录错误，不影响已经完成的迁移。

测试覆盖：备份大小不随对话正文增长、字节级回滚、CRLF/末尾无换行、追加事件、
元数据冲突和截断、写入期间并发变化、无操作修复、旧版完整文件恢复，以及数量、
容量和受保护快照的保留规则。
